# M00 implementation assignment

Deliver a working static browser cantilever calculator with original WebGPU viewport, Rust/WASM solve, editable inputs, numerical results, project save/reopen and standalone calculation report. Read SPECIFICATION.md sections 2, 5–8 and contracts/PROTOCOL.md first. The user requires plain HTML/JS/CSS, Rust WASM and WebGPU; do not substitute a framework or server solver.

## Acceptance tour

1. From a clean local build, serve the static directory on localhost and open the app.
2. Choose the synthetic 3 m cantilever. Show units and all section/material values used.
3. Enter 10 kN downward at its free end and run the real kernel.
4. Show −45 mm global Z tip displacement, +0.0225 rad rotation about Y, +10 kN vertical support reaction and −30 kN m support moment, within B02 tolerances.
5. Double Iy and verify the displacement halves after a new solve, while equilibrium reactions remain unchanged. Before rerun, show the previous result as stale.
6. Select the member in the WebGPU viewport and inspect a result value linked to its ID.
7. Export project JSON and a small calculation report. Close/reopen/import and reproduce the engineering hash and results.
8. Remove the fixed support in the UI. Analysis must return a structured instability result without numeric zero placeholders.
9. Exercise a mocked unavailable adapter; tables and export remain available with a clear capability explanation.

## Required engineering work

Pin actual Rust/wasm-bindgen/JS test dependencies and runtime versions in lockfiles. Compile the selected sparse solver to wasm32-unknown-unknown and run B01–B04 both natively and in browser WASM. Introduce one solver trait, small-matrix element operations and a schema-backed Rust model; no large generic CAD framework. Include an explicit 12-DOF matrix and sign-convention dossier. Do not hide an unavailable sparse backend behind an unbounded dense solve.

Provide npm run build, the applicable validation commands, a local preview command and the milestone gate. Dist must contain static HTML/CSS/JS/WGSL/WASM assets and no required backend. Report any unavailable external oracle/hardware runner explicitly; M00 can validate its analytical use case while preparing later resource gates.

## Evidence to hand off

Source commit, clean build log, lockfile hashes, result JSON for B01–B04, native/WASM comparisons, UI trace for the tour, one WebGPU screenshot, exported project/report, invalid-model diagnosis, capability manifest and performance baseline. Every screenshot/result must come from the implemented app. Do not use the expected fixture values as UI output.

## Continue rule

When the gate passes, advance to M01 without asking for routine approval. If blocked, write a reproduction and exact missing resource, continue independent work and leave the gate truthfully blocked. Follow actual environment policy for any external deployment.
